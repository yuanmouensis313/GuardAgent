# GuardAgent deployment, rollback, and troubleshooting

GuardAgent is an additional execution-point control. It does not replace OpenClaw sandboxing, tool policy, exec approvals, channel pairing, or operating-system isolation. A compromised Gateway or native code that bypasses the OpenClaw tool lifecycle is outside the plugin's security boundary.

## 1. Prerequisites and conservative defaults

- Python 3.12 or newer and Node.js 22 or newer.
- OpenClaw on Windows, WSL2, or Linux. Docker/SSH sandbox backends are preferred over unsandboxed host execution.
- One explicit workspace root. Do not use a user home directory, drive root, Docker socket, OpenClaw state directory, or GuardAgent repository as the monitored workspace.
- External channels must use pairing or a sender allowlist. Group and direct-message policies must be separate.
- Network egress starts disabled. Add only required domains to `policies/default.yaml` after Observe-mode review.

The default GuardAgent mode is `observe`: guardd records both the effective `OBSERVE` result and the proposed decision without blocking. OpenClaw native policy and the plugin's hard-coded degraded-mode emergency controls remain authoritative. Switch to Approval/Enforce only after the rollout gates below are met.

## 2. Install and initialize

```powershell
python -m pip install -e ".[test]"
python scripts/init_guard.py
guardd
```

In a second terminal:

```powershell
guardctl status
guardctl policy validate
guardctl doctor
```

`init_guard.py` creates a random bearer token. Do not copy the token into OpenClaw config or logs; configure only its file path. On Windows, restrict the state directory and token using the current user's ACL. On POSIX, the initializer applies mode `0700` to the state directory and `0600` to the token where supported.

## 3. Build and install the plugin

```powershell
cd plugins/guard-openclaw
npm install --ignore-scripts
npm run check
npm run build
```

Use the generated `dist/index.js`. The manifest is `openclaw.plugin.json`; OpenClaw source and runtime entries are paired in `package.json` as required by the current Plugin SDK. Install the reviewed local package explicitly with `openclaw plugins install <absolute-path-to-plugins/guard-openclaw>`; the baseline config intentionally does not use a mutable plugin load path.

Copy `config/openclaw-security-baseline.json5` and replace all placeholders. Merge it manually; do not let the monitored agent alter OpenClaw or GuardAgent configuration. Copy `config/exec-approvals.baseline.json` to the active execution host's `exec-approvals.json`, preserving any socket object generated by OpenClaw. Keep `askFallback: "deny"`, `autoAllowSkills: false`, and strict inline eval enabled.

The install policy defaults to denying every install. Set `GUARD_INSTALL_ALLOWLIST` to a comma-separated exact target-name allowlist and `GUARD_INSTALL_LOCAL_ROOTS` to an OS-path-separator-delimited list of trusted canonical source roots. For network installs, also set `GUARD_INSTALL_REGISTRIES` to approved registry hostnames; only immutable npm/ClawHub sources pinned to an exact version are accepted.

## 4. Required baseline verification

Run after every deployment and OpenClaw upgrade:

```text
openclaw doctor
openclaw security audit
openclaw security audit --deep
openclaw sandbox explain --agent main
openclaw exec-policy show
openclaw approvals get
guardctl doctor
```

Do not enter Enforce mode if any of these show sandbox disabled, host/root/home mounts, Docker socket exposure, elevated access, `security=full`, `ask=off`, wildcard senders, an unavailable install policy, or a disabled GuardAgent plugin.

## 5. Observe, Approval, and Enforce rollout

1. Run Observe for at least three days (seven is preferred) and review `guardctl events list`.
2. Exercise allow, deny, timeout, guardd-disconnect, database-error, and approval paths.
3. Change `defaults.mode` to `approval`, validate, and restart/reload only from an operator terminal.
4. Move to `enforce` only when the high-risk fixture set has zero false allows and normal work has acceptable false positives.

Policy changes are schema-validated before loading. An invalid update does not replace the currently loaded policy. Back up OpenClaw config, GuardAgent policy, and the SQLite state before each transition.

Create a transactionally consistent database backup from an operator terminal with `python scripts/backup_guard.py <destination.sqlite3>`; the command reports the backup SHA-256 and integrity result.

## 6. Terminal operations

```text
guardctl events list --session <hashed-session>
guardctl approvals list
guardctl approvals allow-once <uuid>
guardctl approvals deny <uuid>
guardctl policy simulate fixtures/deny/root-delete-posix.json
guardctl policy test fixtures/deny/root-delete-posix.json
guardctl replay --session <hashed-session>
guardctl ui
```

Approvals expire after 60 seconds by default, are single-use, and bind agent, session, sender, tool, parameters, cwd, normalized paths, and network targets. Critical decisions never offer an approval path. OpenClaw plugin approvals offer only `allow-once` and `deny`.

### Local visual console

Run `guardctl ui` from a trusted local operator terminal. The command verifies `guardd`, creates a 60-second single-use bootstrap code, and opens the loopback-only console. Use `guardctl ui --no-open` when the environment cannot launch a browser.

The console provides overview metrics, live approval handling, event and session timelines, candidate-policy validation/simulation/regression, atomic policy publishing and rollback, incidents, diagnostics, and read-only settings. Browser writes require an HttpOnly UI session, a per-session CSRF token, and an allowed loopback Origin. The bearer token remains in the protected state directory and is not copied into the browser.

If the UI build is unavailable, `/ui/` returns 503 while `/v1/*`, the plugin, and all existing CLI operations continue to work. UI sessions and pending approvals are invalidated by a service restart.

Set `GUARDD_UI_ENABLED=false` before starting `guardd` to disable the browser control plane entirely. Machine APIs and the OpenClaw plugin remain available; `/ui/` returns 503 and `/v1/ui/*` is not registered.

## 7. Failure behavior

- `guardd` unavailable or timed out: the plugin permits only verified workspace reads, denies external/sensitive reads, security changes, outbound data, dynamic eval, host/elevated execution, and external writes; other actions require native one-time approval. Reconnect uses exponential backoff.
- SQLite write failure: high-risk decisions fail closed. Critical/deny audit records fall back to the protected emergency JSONL.
- Policy parse failure: the last valid in-memory policy remains active. If there is no valid startup policy, `guardd` refuses to start.
- Missing approval UI, timeout, malformed resolution, restart, or missing record: deny.

## 8. Rollback and break-glass

Rollback is an operator-only action outside OpenClaw:

1. Stop the Gateway.
2. Preserve the SQLite database, emergency JSONL, current policy digest, OpenClaw config, and security-audit output.
3. Restore the last known plugin artifact, policy, and OpenClaw configuration backup.
4. Restart `guardd`, then Gateway, and rerun every baseline command and adversarial fixture.

Emergency break-glass may disable the plugin only while the Gateway is stopped and only from a trusted local operator terminal. It must not enable YOLO/full access, elevated execution, wildcard tool access, or `askFallback: allow`. Record the operator, reason, timestamps, and restored configuration in an incident record. Re-enable and re-audit before resuming agent work.

## 9. Troubleshooting

- HTTP 401: confirm both processes reference the same token file; rotate by stopping both, replacing the file, and restarting.
- Repeated degraded-mode approvals: verify `guardd` listens only on loopback and plugin timeout is below 500 ms and below the OpenClaw hook timeout.
- Plugin discovery failure: validate `openclaw.plugin.json`, ensure `dist/index.js` exists, and run `openclaw plugins inspect guard-openclaw --runtime --json`.
- Pending approvals after restart: they are intentionally invalid; list and deny/expire them.
- SQLite contention: confirm WAL and `busy_timeout`, ensure no monitored-agent mount includes the state directory, and run an integrity check through `guardctl status`.
- Install policy blocks an intended package: pin an exact version, add only its exact target name to `GUARD_INSTALL_ALLOWLIST`, rerun deep doctor, and remove temporary trust after installation.

Audit retention defaults to 30 days as configuration metadata; production scheduling for database backup/retention must run outside OpenClaw. Never let the monitored agent rotate or delete GuardAgent logs.
